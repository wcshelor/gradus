## Representative evidence

```python
p = ScorePosition(quarters=Fraction(7,4), measure_index=2, measure_number="3",
                  offset_in_measure=Fraction(3,4), voice="1", staff=1, hand="right")
iv = ScoreInterval(start=..., end=...)  # start.quarters < end.quarters enforced
d = iv.to_dict()  # {"schema_version":"score_interval.v1","start":{...},"end":{...}}
assert ScoreInterval.from_dict(d) == iv
assert json.dumps(d, sort_keys=True) == json.dumps(ScoreInterval.from_dict(d).to_dict(), sort_keys=True)
assert not iv.contains_quarters(iv.end.quarters) # half-open
```

Golden payloads are intentionally not frozen yet beyond unit assertions; WP-01 will freeze one compact JSON per T01.4.

## Unsupported and ambiguous cases

- Fraction deserialization rejects `float` with `ValueError: lossy float fraction rejected` per Global limits (exact rational time).
- `ScoreInterval` rejects empty (`start==end`) and inverted intervals with `ValueError: non-empty half-open [start,end)`.
- `ScoreInterval` rejects `measure_index` inconsistent with `quarters` ordering (e.g., start measure 5, end measure 0 with increasing quarters) — treats as invalid interval (strict quarters is canonical, but index must be monotonic).
- Unsupported `schema_version` raises `ValueError` listing supported versions; not silently accepted.
- No passage selection implemented (per T01.1 limit).

## Known limitations

- WP-01 incomplete: T01.2–T01.4 not yet implemented; no `PassageSelection` or view containers. `ScorePosition`/`ScoreInterval` are standalone; downstream consumers (WP-02) not yet wired.
- No ID resolver yet (Q-001); positions are values, not yet linked to stable source IDs.
- Contract-version policy is code-enforced via `SUPPORTED_*_VERSIONS` sets but not yet documented in `docs/contracts.md` versioning policy table — will be added with T01.4 when passage/view containers freeze.
- Hand/voice/staff are simple strings/ints; not yet enriched with confidence enums (deferred to T01.3 diagnostics).
